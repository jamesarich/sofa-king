# Sofa King

Three Gradle builds: the app in `app/` (rules in `app/AGENTS.md`), the server in `backend/` (rules in `backend/AGENTS.md`) and the wire types both include in `contract/` (rules in `contract/README.md`). The root `settings.gradle.kts` only includes them for one IDE import; build each from its own directory through `/home/james/.claude/bin/gradle-queue -C app --`, `-C backend --` or `-C contract --` from the repository root. All three share `gradle/libs.versions.toml` (the one version catalog), `gradle/repositories.settings.gradle.kts`, `gradle/build-cache.settings.gradle.kts` (the remote build cache) and the convention plugins in `build-logic/`: `sofaking.kotlin` (locking, JDK 21, web toolchain repositories) and `sofaking.android` (SDK levels).

A wire change goes in `contract/` and lands with both sides in one pull request; the server must keep every field of the fixtures in `contract/src/jvmTest/resources/wire`, because the TV runs an older app than the server it talks to.

CI: `.github/workflows/ci.yml` (calls `snapshot.yml`) runs for changes under `app/` or `contract/`, `backend.yml` for `backend/` or `contract/`, Markdown excluded; a push to `main` that changes the server publishes `ghcr.io/jamesarich/sofa-king-backend:main`, which the home server installs within about 20 minutes. Commits use Conventional Commits; squash-merge pull requests after CI is green at the head.

Docs: the root keeps `README.md`, `CONTRIBUTING.md` (layout, commits, pull requests, CI), `SECURITY.md` (reporting) and `docs/README.md` (the index and shared glossary). `app/` and `backend/` each keep a `README.md` and a `docs/` folder with the same page set where it applies (`README.md` index, `getting-started.md`, `troubleshooting.md`, `architecture.md`, `security.md`, `development.md`, `dependencies.md`); put a new page in the part it describes and link it from that index. Write current facts in the present tense, with steps in the imperative, in the existing voice.
