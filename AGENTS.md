# Sofa King

A self-hosted media center: live TV, recordings and media libraries on one server, and one app that watches them. Three Gradle builds: the app in `app/` (rules in `app/AGENTS.md`), the server in `backend/` (rules in `backend/AGENTS.md`) and the wire types both include in `contract/` (rules in `contract/README.md`). The root `settings.gradle.kts` only includes them for one IDE import; build each from its own directory. On the shared host, run `/home/james/.claude/bin/gradle-queue -C app --`, `-C backend --` or `-C contract --` from the repository root; anywhere else (CI, a container, a fresh machine) run `./gradlew` from `app/`, `backend/` or `contract/`. All three share `gradle/libs.versions.toml` (the one version catalog, including `sofaking`, the one product version, which `.github/version.sh` extends with the build number both the app snapshot and the server image carry), `gradle/repositories.settings.gradle.kts`, `gradle/build-cache.settings.gradle.kts` (the remote build cache, read-only without the `SOFAKING_CACHE_*` credentials) and the convention plugins in `build-logic/`: `sofaking.kotlin` (JDK 21, web toolchain repositories) and `sofaking.android` (SDK levels). Versions are exact pins in the catalog with no lockfiles and no verification metadata; Renovate opens the update pull requests. `.gitignore` ignores every directory named `build`, so no package or source directory may carry that name.

Every build runs `spotlessCheck detekt` in CI (the `sofaking.lint` convention: ktlint through Spotless, detekt with the Compose rules). Run `./gradlew spotlessApply` before committing and fix detekt findings in the code: there is no baseline, no build turns a rule off, and a narrow `@Suppress` needs a comment saying why. A catch-all goes through `runCatchingCancellable`, never a bare `catch (e: Exception)`. CONTRIBUTING.md#formatting-and-static-analysis has both rules. Check a docs change with `python3 docs/site/stage.py && mkdocs build --strict` (in a venv from `docs/site/requirements.txt`).

Run the checks for what you changed before you push, and push fixes together: a pull request is not where code first compiles. In a cloud container, `.claude/skills/cloud-build` says what builds there (the Android SDK, Maven Central's rate limit, the lint CLIs) and what only CI can check; `.claude/skills/ci-failure` reads a red run and lists the known flakes before a re-run; `.claude/skills/emulator-check` covers checks on an emulator or simulator, and turning one into a Maestro flow in `app/maestro/` that `tv-monkey.yml` runs every night.

`CLAUDE.md` in each part only imports its `AGENTS.md`; edit the `AGENTS.md`. Commits, pull requests and GitHub comments carry no AI attribution (no `Co-Authored-By` or session trailers, no "Generated with" footers); `.claude/settings.json` turns it off for Claude Code.

A wire change goes in `contract/` and lands with both sides in one pull request; the server must keep every field of the fixtures in `contract/src/jvmTest/resources/wire`, because the TV runs an older app than the server it talks to.

CI: `.github/workflows/ci.yml` (calls `snapshot.yml` and `publish-snapshot.yml`) runs for changes under `app/` or `contract/`, `backend.yml` for `backend/` or `contract/` (and, on a push to `main`, for the app's `core` and `ui`, since the image serves the web app built from the same commit at `/app/`); both also run for `gradle/`, `build-logic/` and their own workflow file, and neither runs for Markdown or the `docs/` folders (`ci.yml` also skips the Maestro flows and the monkey and screenshot scripts, which their own workflows run); `docs.yml` builds the Markdown as the MkDocs site (`mkdocs.yml`, strict, so broken links fail) and publishes it to GitHub Pages from `main`. `dependency-submission.yml` sends each build's dependency graph to GitHub from `main`, for Dependabot alerts. `codeql.yml` scans the workflows weekly, and `scorecard.yml` rates the repository's supply chain on each push to `main`. Every published package carries a build attestation, and the image a cosign signature too. `tv-monkey.yml` runs nightly: the Maestro flows in `app/maestro/`, then random remote keys, on the debug app in a headless Android TV emulator. `desktop-monkey.yml` does the same for the desktop app in Xvfb, with libVLC playing. `phone-tests.yml` runs the debug app's touch tests (picture-in-picture, predictive back, rotation, random touches) in a headless Android phone emulator. `screenshots.yml`, run by hand and on pull requests that change it or its scripts, takes the README's screenshots on every platform a runner can show against a showcase lineup of open movies (`app/docs/development.md#screenshots`). A push to `main` that changes the app publishes the rolling `snapshot` prerelease; one that changes the server publishes `ghcr.io/jamesarich/sofa-king:main`, which the home server installs within about 5 minutes. A `v*` tag matching the catalog's `sofaking` runs `release.yml` (calls `snapshot.yml` and `publish-release.yml`), which publishes the `vX.Y.Z` release, and `backend.yml`, which publishes the image as `:X.Y.Z`, `:X.Y` and `:latest`. Commits use Conventional Commits; squash-merge pull requests after CI is green at the head.

Language: write US English everywhere: docs, comments, UI copy, log messages, commit messages, pull requests, and the names of our own files, classes, functions and variables. Spell it color, behavior, center, gray, license, catalog, canceled and canceling, optimize, recognize and serialize, and say program (not programme), movie (not film) and while (not whilst). Names that belong to someone else keep their spelling: the XMLTV `<programme>` element and a third-party API's fields. Our own stored names move with a migration, as `V208__program_names.sql` moved `guide_programme` and the `cancelled` recording state.

Docs: the root keeps `README.md`, `CONTRIBUTING.md` (layout, commits, pull requests, CI, the docs site), `SECURITY.md` (reporting), `SUPPORT.md` (where to ask), `CODE_OF_CONDUCT.md` (the Contributor Covenant) and `docs/` (`README.md`, the index and shared glossary; `comparison.md`; `migrating.md`; `site/`, the MkDocs build that `mkdocs.yml` publishes). A new page also goes in `mkdocs.yml`'s `nav`. `app/` and `backend/` each keep a `README.md` and a `docs/` folder with the same core pages (`README.md` index, `getting-started.md`, `troubleshooting.md`, `architecture.md`, `security.md`, `development.md`, `dependencies.md`), plus the app's `usage.md` and the server's `api.md`, `admin.md`, `deploy.md`, `operations.md`, `live-tv.md`, `notifications.md`, `integrations.md`, `recordings.md`, `libraries.md`, `virtual-channels.md`, `providers.md`, `lineup-policy.md`, `source-health.md` and `starter-lineup.md`; put a new page in the part it describes and link it from that index. Write current facts in the present tense, with steps in the imperative, in the existing voice.
