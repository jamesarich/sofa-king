# Sofa King

Three Gradle builds: the app in `app/` (rules in `app/AGENTS.md`), the server in `backend/` (rules in `backend/AGENTS.md`) and the wire types both include in `contract/` (rules in `contract/README.md`). The root `settings.gradle.kts` only includes them for one IDE import; build each from its own directory. On the shared host, run `/home/james/.claude/bin/gradle-queue -C app --`, `-C backend --` or `-C contract --` from the repository root; anywhere else (CI, a container, a fresh machine) run `./gradlew` from `app/`, `backend/` or `contract/`. All three share `gradle/libs.versions.toml` (the one version catalog, including `sofaking`, the one product version), `gradle/repositories.settings.gradle.kts`, `gradle/build-cache.settings.gradle.kts` (the remote build cache, read-only without the `SOFAKING_CACHE_*` credentials) and the convention plugins in `build-logic/`: `sofaking.kotlin` (JDK 21, web toolchain repositories) and `sofaking.android` (SDK levels). Versions are exact pins in the catalog with no lockfiles and no verification metadata; Renovate opens the update pull requests. `.gitignore` ignores every directory named `build`, so no package or source directory may carry that name.

A wire change goes in `contract/` and lands with both sides in one pull request; the server must keep every field of the fixtures in `contract/src/jvmTest/resources/wire`, because the TV runs an older app than the server it talks to.

CI: `.github/workflows/ci.yml` (calls `snapshot.yml`) runs for changes under `app/` or `contract/`, `backend.yml` for `backend/` or `contract/`; both also run for `gradle/`, `build-logic/` and their own workflow file, and neither runs for Markdown or the `docs/` folders. `dependency-submission.yml` sends each build's dependency graph to GitHub from `main`, for Dependabot alerts. A push to `main` that changes the app publishes the rolling `snapshot` prerelease; one that changes the server publishes `ghcr.io/jamesarich/sofa-king:main`, which the home server installs within about 20 minutes. Commits use Conventional Commits; squash-merge pull requests after CI is green at the head.

Docs: the root keeps `README.md`, `CONTRIBUTING.md` (layout, commits, pull requests, CI), `SECURITY.md` (reporting) and `docs/README.md` (the index and shared glossary). `app/` and `backend/` each keep a `README.md` and a `docs/` folder with the same core pages (`README.md` index, `getting-started.md`, `troubleshooting.md`, `architecture.md`, `security.md`, `development.md`, `dependencies.md`), plus the app's `usage.md` and the server's `api.md`, `admin.md`, `deploy.md`, `operations.md`, `live-tv.md`, `providers.md`, `lineup-policy.md`, `source-health.md` and `starter-lineup.md`; put a new page in the part it describes and link it from that index. Write current facts in the present tense, with steps in the imperative, in the existing voice.
