# Sofa King app

The media center's client: live TV (Live), media libraries (Library) and recordings (DVR) from a Sofa King server. Kotlin Multiplatform: `core` (data, no Compose, every target its dependencies publish), `ui` (Compose Multiplatform screens for Android, JVM desktop, iOS, js and wasmJs), `androidApp` (the Android TV app shell), `baselineprofile` (the Baseline Profile generator), `iosApp` (SwiftUI host) and `tvosApp` (the SwiftUI Apple TV app on `core`'s `SofaKingTv`, since Compose does not render on tvOS, plus its `TopShelf` extension, which reads the recent channels through the `group.dev.jamesrich.sofaking` app group). The two Swift hosts are generated by XcodeGen from their `project.yml`; no `.xcodeproj` is committed. Read README, docs/README.md and docs/architecture.md for current setup and behavior.

## Build

Use JDK 21 and an Android SDK configured in `app/local.properties` (`sdk.dir=...`, ignored by Git; a new worktree needs a copy). The app's Gradle build is `app/`; on the shared host, run from the repository root:

```sh
/home/james/.claude/bin/gradle-queue -C app -- spotlessCheck detekt :core:allTests :ui:jvmTest :ui:testAndroidHostTest :ui:jsNodeTest :androidApp:lintDebug :androidApp:assembleRelease :androidApp:testDebugScreenshotTestDefaultTestSuite
```

Elsewhere run `./gradlew` with the same tasks from `app/`. After a change to common code also run `:core:compileTestKotlinLinuxX64 :core:compileKotlinLinuxArm64 :ui:compileTestKotlinIosSimulatorArm64`, which CI runs too: Native rejects commas and parentheses in backtick test names and JVM-only APIs that the JVM accepts. CI's Linux job adds `:ui:wasmJsBrowserDistribution :ui:jsBrowserDistribution`, the production web builds the snapshot ships; its macOS job runs the Apple simulator tests, links the iOS and tvOS frameworks and builds both Swift hosts with `xcodegen` and `xcodebuild`, so an Apple-only break shows only there. Unit tests run against Ktor's `MockEngine` (`FakeHttp` in `core` common tests), MockWebServer for JVM socket cases, and fakes; no server is needed for offline development. `RenderSmokeTest` draws the main screens headless at TV size into `ui/build/screenshots`. The screenshot suite compares `@PreviewTest` previews against `androidApp/src/screenshotTestDefaultDebug/reference`; after an intended visual change, commit references that Linux drew, since a Mac renders some screens differently and CI compares on Linux: run `:androidApp:updateDebugScreenshotTestDefaultTestSuite` on Linux, or take the PNGs from the failing run's `reports-linux` artifact (`androidApp/build/intermediates/debug/testDebugScreenshotTestDefaultTestSuite/results/rendered/`), and look at each before committing it. `androidApp` has no product flavor (`compileDebugKotlin`, `assembleDebug`); the `Default` in those names is the screenshot test suite. Common tests also run on JS, where a `Float` is a double: compare a computed float with a tolerance, not with `assertEquals` against a constant the compiler folded. Install release builds on TVs only when requested; release APKs use R8 and the release key when one is set, otherwise the local debug key (`docs/development.md#signing`).

One test class: `/home/james/.claude/bin/gradle-queue -C app -- :ui:jvmTest --tests 'dev.jamesrich.sofaking.ui.preview.PreviewDwellTest'` (`:core:jvmTest` for the data layer, `:ui:testAndroidHostTest` for the Android host tests).

A change to playback, focus or the remote also needs the TV checklist in docs/development.md, which only a person with a TV can run; say so rather than claiming it. docs/development.md#over-adb has the adb probes for focus, keys and playback, and the `android layout` helper's clash with `uiautomator dump`. The Baseline Profile under `androidApp/src/release/generated/baselineProfiles` is recorded on a device with `:androidApp:generateBaselineProfile`, never by CI; regenerate it after a large change to startup, the guide or the player.

Versions are pinned exactly in the catalog, with no lockfiles; docs/dependencies.md has the update steps. The product version is `sofaking` in the catalog; snapshots pass `-Psofaking.versionCode` and `-Psofaking.versionSuffix`. Commits use Conventional Commits, `type(scope): summary` in the imperative, scoped by area: `app` (the shell, navigation and the tabs), `guide`, `player`, `preview`, `captions`, `settings`, `library`, `data`, `web`, `ios`, `tvos`, `desktop`, `build`, `ci`, `docs`.

## Code map

All source is under `dev.jamesrich.sofaking`; tests mirror it in each module's `commonTest`, `jvmTest` or `androidHostTest`. Read the source for the file layout; these are the placement rules it doesn't show:

- Key mapping, back, focus and timing decisions are plain functions or classes beside the composables (`guideBackAction`, `PreviewDwell`, `launchTarget` and their neighbors), unit-tested without a device; put new decisions there too.
- Anything two feature packages share lives in `ui/.../ui` (`Adaptive.kt`, `Focus.kt`, `theme/` and the other top-level files), so `guide`, `library`, `player`, `preview`, `recordings` and `settings` never depend on each other in a cycle.
- `core/.../data/ServerConnection` is the one process-wide link to the server: its API client, capabilities, the one `PlaybackSessions`, the `RecordingSchedule` and the preference sync. Every ViewModel plays through it.
- `ui/.../App.kt` is the shell: the ViewModels, the player and its lifecycle, and the Navigation 3 routes. Its state and moves are unit-tested in `AppShellState.kt` and `Navigation.kt`.

## Code placement

- Put code in `commonMain`. A platform source set holds only what needs that platform's API, behind an `expect` or an interface; `LivePlayer`, `rememberVoiceSearch`, `rememberIsTelevision`, `KeepScreenOn`, `rememberPlayerWindow`, `rememberScreenReaderActive` and the key-repeat accessors are the seams; a desktop window's or browser page's full screen comes in through `App`'s `WindowFullScreen`.
- `core` stays free of Compose so a native host can use it. Its models are plain data classes; `ui/compose-stability.conf` marks them stable.
- Wire objects through constructors; `AppGraph` in `ui` holds the one settings store and the one `ServerConnection`, `initSofaKing` starts it once per process from each entry point, and the shell gets each ViewModel from lifecycle's `viewModel { appGraph.… }`. A ViewModel never takes another ViewModel or its fields; what several share belongs in the data layer (`ServerConnection`).
- State flows one way. ViewModels expose immutable `StateFlow`s, setters that return `Unit` and no coroutine handles; a short action whose result matters only while its screen is up (record, delete, search, play) may be a `suspend` function the screen awaits. A destination collects what it shows with `collectAsStateWithLifecycle`, as low in the tree as it is read. Work that must outlive a screen (pairing, saving) runs in `viewModelScope` and reports its outcome as state the screen acts on and acknowledges (`PairingState.outcome`, `pairingHandled`), never as a value returned to a composition's coroutine scope. Keep UI-only state and moves in a plain state holder (`AppShellState`, `GuideState`, `PlayerState`, `VodPlayerState`) or beside the composable.
- No `java.*`, `android.*` or JVM-only collection APIs in common code: `kotlin.time` for instants and durations, kotlinx-datetime for wall-clock formatting, kotlinx-io for files, Ktor for HTTP, Kermit for logs, `kotlin.uuid` for ids.

## UI

- Use multiplatform Material 3 Expressive components under `SofaKingTheme`. Add `tvFocus` (or use `SofaButton`) to every focusable control so D-pad focus shows; guide cells and Settings rows keep scale 1. A switch setting is a `ListItem` made `toggleable` so the whole row takes focus, and a choice of a few values is a `SingleChoiceSegmentedButtonRow`.
- Support the five-way D-pad and its keyboard equivalents. Use focusRestorer; request focus from effects or callbacks and wait for lazy nodes with requestFocusWhenAttached. The guide's first focus is retried until a cell reports it landed; the header's buttons must never keep focus once channels are on screen, except after Back from another tab or leaving Settings (`Arrival.inHeader`), which keeps it on the Live tab or the Settings button until focus comes down into the guide. The unconfigured screen focuses the header's Settings button (`homeFocusFor`).
- Preserve 48dp horizontal and 27dp vertical overscan padding on TV. Pad screens with `screenPadding` (`ui/Adaptive.kt`), which keeps the overscan on TV and the safe-drawing insets everywhere else; never hard-code the margins.
- Lay out by `LocalLayoutProfile`: a TV (`rememberIsTelevision`) keeps today's metrics at any size, and other windows adapt by the window size class from `currentWindowAdaptiveInfoV2()` (compact width under 600dp, compact height under 480dp). Touch and mouse controls show only after pointer input (`LocalLastInput`), so the TV's screens never change; that includes a page's own Back button (`showsBackButton`), which a TV leaves to the remote's Back key.
- Preserve the guide's 24-hour window, filter and scroll across player navigation. Back from the player focuses the channel being watched (`returnedFrom` ranks first in `initialGuideRow`), shows All when a filter or search hides it, and keeps the time cursor no earlier than now.
- A cold start opens the last watched channel full screen through the normal session path, decided once by `launchTarget` after the settings and (for Live) the lineup are in; the cached channels arrive before their programs are decoded, so a cold start does not wait on the guide; the guide and preview must not compose before that decision. No last channel opens the guide. Open on start's default, Where I left off, reopens the tab remembered in `AppSettings.lastTab` instead when it is Library or Recordings, with nothing playing.
- Guide and Menu are one shortcut: in the player they open the guide at Now (`Arrival(atNow)`), in the guide they jump to Now. Search opens guide search through `rememberVoiceSearch`, falling back to the text field when the platform has no recognizer. Map remote keys in `playerExit` and `guideShortcut`, not in ad-hoc `when` branches.
- Back in the guide: open search closes first, the grid hands focus to the selected chip, the chips to the header's open tab, and from there Back exits at once, with no press-again step (Google's TV guidance). Decide it in `guideBackAction`, never in a second `BackHandler`; the remote's Back key is taken in the guide's preview key handler (key-down held, climb on key-up), since Compose turns an unhandled Back key-down into a focus exit that can eat the press. `BackHandler` wraps NavigationEvent's `NavigationBackHandler`.
- Navigate with `Navigation`'s moves (`push`, `pop`, `open`, `closeSettings`), never by holding a parent page in a `Route`: the entry below is the parent. One-shot arrival data goes in `Arrival`, and a `Route`'s `id` names its saved state, so it must not change while the page is open.
- Keep models immutable. Read time from rememberMinuteNow, not the clock during composition; rest timers read `uptimeMs`.
- Use theme colors, shared motion and Compose resource strings in US English, without Android escapes (`\'`). UI terminology is "program".

## Playback and data

- The app holds one `LivePlayer` from `rememberLivePlayer`. Preview and full-screen screens borrow it; neither releases it. Each platform implements it (Media3, libVLC, AVPlayer, a video element); screens read its `status`, `errors` and `cues` flows.
- Every stream is a server playback session owned by `PlaybackSessions` in the ViewModel; screens call `tune` and `setIntent`, never the session API directly. The app holds one session at a time.
- The preview opens a `preview` session; OK promotes the same session to `watch` with `setIntent`. Do not reopen or reload on the handoff. The full screen sets the shared player's volume to 1 when it opens, and the preview writes it only while the guide is the page on top, since the guide stays composed for a frame under the player it hands over to.
- The preview's rest timers live in `PreviewDwell` (muted on tune, sound at 5 s, full screen at 10 s, any key restarts both); the auto full screen uses the OK handoff, runs only while a grid cell has focus with search closed, and never refires for the channel the player was just left on until focus moves. It never fires unless the host is STARTED, and ON_START restarts the rest muted. Keep the timing decisions in the class, not in effects.
- Items carry the channel id and the descriptor's MIME type; on Android `mediaItemFor` sets them and Media3 never sniffs a session URL.
- Renew well inside the 45 s preview lease (15 s). Release on channel change, Settings and ON_STOP; reopen on ON_START. Reopen on `replaced` and on a 410 from the relay by re-reading the session, not by retrying the old URL.
- Session opens run under NonCancellable and a canceled tune releases what it opened. Never leak a session: capacity is small and the oldest preview is evicted.
- Gate tune preparation on STARTED. Stop on ON_STOP and Settings; retain paused-user intent on return. These read the app's lifecycle (`appLifecycleOwner`), not a page's: a page's `LocalLifecycleOwner` is its Navigation 3 entry's, which also stops when the page is left.
- Preserve preview debounce and stream handoff. A zap waits `ZAP_SETTLE_MS` for presses to rest (the first tune does not), then stops, resolves the session, sets the item and prepares.
- Reconnect failed/ended streams with the existing backoff. Do not add a watchdog that reconnects stalled-but-open streams. A `CHANNEL_NOT_FOUND` session error reloads the lineup and follows the channel by number, then name; never retry a dead id with the backoff.
- `PlayerScreen` and `VodPlayerScreen` hold the system media session through `LivePlayer.openMediaSession` while the app is started, the newest handle holding it (`NewestMediaSession`); there is no background playback service for video (`MusicService` plays music in the background). Picture-in-picture (Android phones and tablets, never a TV) keeps the activity started, so the stream plays on through the same session; the players draw only the picture while `LocalInPictureInPicture` is true. Android's player asks for audio focus, and iOS's takes the Playback audio session category, only while audible (`volume` above zero), so the muted preview never stops other apps' sound.
- Preserve CEA-608/708 selection, caption geometry and per-channel timing on Android. Update renderer-thread settings from SideEffect through `@Volatile` fields in `CaptionSync`. The preview draws the same `Captions` composable as the full screen, scaled to its box with no overscan inset, gated on the CC setting; the Android player prefers the caption track on every track change.
- When wrapping Media3 Java interfaces, forward every required overload explicitly; do not use Kotlin by delegation. The media session's player (`LivePlayerWrapper`) is a `ForwardingSimpleBasePlayer` that changes the player's `State` and its `handle*` calls.
- Keep sockets and files off the main thread (`ioDispatcher`). Preserve cancellation and close owned calls/listeners/resources.
- Keep DataStore corruption recovery, its Android file path and last-good lineup behavior; the lineup cache adds protobuf fields with new numbers and never renumbers them. Never log or print the API token; `AppSettings.toString` hides it and Settings masks all but its last four characters while the field is not being edited.
- API requests go through `SofaKingApi` with the bearer token; media requests carry none. Transport errors surface as `IOException` on every engine. Guide queries stay within 200 channels and 24 hours.
- The server's request and response types come from `../contract` (aliased in `SofaKingDto.kt` beside `wireJson`, which ignores unknown fields); change a wire field there, never in the app, and follow `../contract/README.md`. Branch on `Wire` constants, not string literals.
