# Code and documentation review — October 10, 2026

Reviewed the Android app and the [native backend](https://github.com/jamesarich/sofa-king-backend) against their implemented behavior, official dependency metadata, [Android coroutine practices](https://developer.android.com/kotlin/coroutines/coroutines-best-practices), [architecture recommendations](https://developer.android.com/topic/architecture/recommendations) and the [GitHub documentation style guide](https://docs.github.com/en/contributing/style-guide-and-content-model/style-guide).

## Findings and fixes

| Priority | Finding | Fix |
| --- | --- | --- |
| High | A preview debounce or initial full-screen tune could prepare after the activity stopped. | Wait for STARTED before preparing and updating tuned-channel state. Preserve the shared player and handoff. |
| Medium | Canceling a feed load could wait up to the socket read timeout. | Own an OkHttp call for the load and cancel it when its coroutine is canceled, including during body parsing. A stalled-body socket test checks prompt disconnect. |
| Medium | Profile query/fragment delimiters changed endpoint paths; a base URL could contain credentials or incompatible suffixes. | Encode the profile as one path segment; validate base authority and reject user info, query, fragment and invalid ports. |
| Medium | Invalid XMLTV intervals could reach the guide layout. | Discard zero or negative durations; test valid rows survive alongside them. |
| Medium | Media3 wrapper usage lacked AndroidX's Java API opt-in. | Use the same AndroidX OptIn convention as the other player classes. |
| Medium | Caption viewport and guide resources used configuration-insensitive APIs. | Read LocalWindowInfo, LocalDensity and LocalResources. |
| Low | Transitive Android dependencies were unlocked; Gradle property strings were interpolated into generated Java without escaping. | Commit resolved dependency locks and generate escaped string literals. |
| Low | Docs described a single reconnect, misstated MediaSession lifetime, included empty screenshot promises and omitted the separate backend. | Document actual reconnect backoff and screen ownership, remove placeholder content and distinguish pending native integration. |

Compose modifier ordering, unused resources and backup/transfer declarations were also corrected. LAN HTTP and landscape TV layout remain intentional project requirements. The banner density warning remains: actual launcher presentation still requires device acceptance.

## Remaining work

Native backend integration must migrate saved numeric channel keys, observe playback descriptors, reopen changed epochs, promote previews and release leases. The Android app currently consumes M3U/XMLTV; a shared compiler version does not establish integration.

JVM tests and lint cannot certify D-pad focus, video surfaces, background/foreground transitions, stream handoff, caption timing or decoder recovery on the target TV. Run the device checks in [development practices](DEVELOPMENT.md) before household cutover. No production server or installed TV app was changed by this review.
