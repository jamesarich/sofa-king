# Code and documentation review — October 10, 2026

Reviewed the backend and [Sofa King Android app](https://github.com/jamesarich/sofa-king) against implemented behavior, current official dependency metadata, Kotlin/coroutine guidance, Android architecture recommendations and the [GitHub documentation style guide](https://docs.github.com/en/contributing/style-guide-and-content-model/style-guide).

## Findings and fixes

| Priority | Finding | Result |
| --- | --- | --- |
| High | Media/feed redirects and nested CDN resources could receive provider secret headers. | Disable automatic redirects; follow at most five explicitly; scope credentials to the original configured origin; reject HTTPS downgrades. Tests cover custom secrets, cookies, nested resources, ranges and loops. |
| High | Cancellation during playback-handle close could skip DELETE, and client shutdown could race a pending creation. | Run bounded cleanup in NonCancellable and serialize creation against shutdown. Tests exercise cancellation and pending creation/close. |
| Medium | XMLTV's default SMART date resolver normalized impossible calendar dates. | Use strict proleptic-year parsing; discard invalid records. |
| Medium | Source-status reads could mix a new published offering list with an older health snapshot. | Capture published offerings before querying health and retain the selected source for update responses. |
| Medium | Evidence older than the six-hour policy window could change current health. | Ignore expired successes and offering failures. |
| Medium | Android's delayed preview and initial player tune could prepare after ON_STOP. | Gate preparation and tune state updates on STARTED, retaining the same shared player. |
| Medium | Android feed cancellation waited on blocking sockets, and profile delimiters could alter endpoint paths. | Own and cancel OkHttp calls across body reads; encode profile segments; reject credentials, queries and fragments in base addresses. |
| Medium | Android lint found missing Media3 opt-in declarations and configuration-insensitive UI reads. | Add the AndroidX opt-in, use current window/resources APIs and apply Compose modifier ordering. |
| Medium | The media smoke selected the first SQLite health row, so parallel imports could make it inspect the unprobed TS fixture. | Select the intended source through the API using its channel UUID; the corrected acceptance run passes. |
| Low | Documentation promised integration, reported stale retry behavior and contained host-specific links and undated evidence. | Separate current behavior from plans, document reconnect backoff and MediaSession ownership, use portable links, language-tagged examples and dated evidence. |

Touched backend source files were expanded into conventional Kotlin formatting with ktlint 1.8.0 and explicit imports. Android dependencies now have resolved lockfiles; both wrappers remain checksum-pinned. This review introduces no mandatory plugin workflow.

## Remaining limits

The Android app still consumes M3U/XMLTV. Native JSON/session integration, favorite-key migration and device acceptance remain next steps. Server-side decoding does not certify TV focus, lifecycle, audio or captions.

Direct FFmpeg probes cannot scope headers per origin. Credential/custom-header feeds are skipped by that worker; playback uses the scoped relay. Qualification through the relay is follow-on work. Cross-origin CDNs requiring secrets need an explicit credential-origin model.

Provider-wide failure correlation, provider capacity reservations, upstream sharing, incident-ledger retention, archival, device pairing/roles and DVR remain documented follow-on work. One household/admin token authorizes both viewing and source administration. This review does not establish production cutover readiness.
